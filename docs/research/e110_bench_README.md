Important correction to a prior chat suggestion: freezing DINOv3 weights does NOT make the interleaved DINO/ViT-Adapter visual features fixed. InteractionBlockWithCls first injects trainable spatial-prior features into patch tokens, then runs frozen DINO blocks, then extracts back into trainable spatial features. Autograd still propagates through DINO operations to train the injector/adapter, and final/intermediate adapted features change with those weights. A simple offline final-DINO-feature cache cannot preserve this training objective. To cache the whole visual front end one must additionally freeze the adapter/front end, or explicitly redesign which paths train. Merely detaching features would silently drop intended adapter gradients. This was established by reading model/vit_adapter/dinov3_adapter/dinov3_adapter_modules.py:202 and dinov3_vit_adapter.py interaction loop; no training configuration changed. Frame-batch size, support count, memory length and trainable scope remain variables requiring a measured benchmark before revising throughput estimates.
