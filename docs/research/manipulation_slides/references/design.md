# Design and editing guide

- Format: 16:9, 19 main slides and 3 appendix slides.
- One claim per slide. Put implementation details and limitations in notes.
- Model names in diagrams: **FM**, **ViT**, **TCOW**. Explain weight provenance in prose; do not turn initialization into a model name.
- Colors: navy `#17324d`, teal `#078981`, blue `#3979b5`, violet `#7954a3`, orange `#d58b27`.
- Font: DejaVu Sans; PDF figure fonts are embedded. If the font is unavailable in PowerPoint, install DejaVu Sans or replace it consistently.
- Figure source: `code/figures.py`. Data and source image captions must remain attached when figures are reused in a paper.
- The workspace is actual accepted-cell occupancy with the original detailed arm visual meshes. Its 3D render and importable GLBs are generated by code. The separate demonstration-path figure retains a simplified robot.
- Never label the recorded scene panels as learned predictions or claim the conceptual flow interpolation is an actual policy trajectory.
- Preserve the distinction between a 2D input prompt and 3D training supervision.
- Keep e105 results blank until its learned policy is evaluated.
- Full metric tables and the temporal-ensemble side experiment belong in the appendix, not the main narrative.
