# Feasible workspace — web 3D assets

Import **[models/workspace.glb](models/workspace.glb)** into your website or 3D editor. It contains the real NexArm visual mesh at the recorded home pose and the translucent boundary of the validated voxel map. All assets are generated by code from the project's meshes and reachability data.

## Assets

| File | Contents |
|---|---|
| `models/workspace.glb` | Robot + translucent voxel boundary; recommended for web import. |
| `models/arm_home.glb` | Robot only; web mesh capped at 10,000 triangles per link. |
| `models/arm_home_original.glb` | Robot only, with original STL triangles and no decimation. |
| `models/voxels.glb` | Translucent voxel boundary only, aligned with the robot. |
| `voxel_centers.f32` | All 32,017 centers, little-endian float32 XYZ in exported coordinates. |
| `metadata.json` | Units, coordinate transform, cell size, counts, and mesh details. |
| `index.html`, `viewer.js`, `vendor/` | Offline viewer with orbit, zoom, opacity, visibility, and PNG export. Three.js 0.170.0 is bundled under its MIT license. |
| `previews/` | Rendered previews, including a transparent-background PNG for slides. |

The GLB files are self-contained and need no external textures or network requests. Link nodes start with `Arm__`; voxel nodes start with `Voxels__`. Their materials use standard glTF alpha blending, default opacity 0.08. A separate `VoxelEdges` node contains the faint square grid as standard glTF line primitives. Lighting, ground grid, and UI belong to the viewer rather than the GLB.

## Open the viewer

From this folder on your own machine:

```bash
python -m http.server 8080 --bind 127.0.0.1
```

Open `http://localhost:8080`. Use an HTTP server because browsers restrict local `file://` model loading. No build step or internet connection is needed.

## Import into Three.js

```js
const { scene: model } = await new GLTFLoader().loadAsync('/assets/workspace.glb');
scene.add(model);
model.traverse(node => {
  if (node.isMesh && node.name.startsWith('Voxels__')) {
    node.material.transparent = true;
    node.material.opacity = 0.08;  // adjust to taste
    node.material.depthWrite = false;
  }
});
```

The included `viewer.js` is a complete working example. For instanced cubes, read `voxel_centers.f32` as a `Float32Array`, and use a cube edge of 0.02 meters.

## Coordinates and interpretation

- Units: **meters**, with **Y up**. No rescaling is needed on import.
- Export origin: robot base. Original base coordinates `[x, y, z]` become glTF `[x, z, -y]`; the inverse is `[X, -Z, Y]`.
- The arm uses the original detailed STL visual geometry, transformed using MuJoCo forward kinematics at the recorded home pose. It is a static mesh assembly; joint animation is not supplied.
- The voxel asset is the **exact exposed faces of the accepted voxel union**, with internal faces omitted to reduce overdraw. The complete center set is supplied separately. No smoothed hull or invented reachability region replaces the actual map.
- These are 32,017 physically validated voxel-center trajectories out of 72,030 candidates, with 34,452 IK-valid goals. This does not certify every point inside each cube.
- Original robot asset ownership/licensing is unchanged.

## Rebuild

From the parent presentation folder, use the normal figure dependencies plus `trimesh` and `fast-simplification`:

```bash
python code/export_workspace_3d.py
```

This uses the frozen `data/arm_visual_home.npz` and `data/workspace.npz`. To re-extract the arm from the original project assets, run `python code/freeze_arm_visual.py` first; that optional extraction requires MuJoCo and the original asset tree.

For automated previews, install Playwright and Chromium, then run `python code/render_workspace_3d.py`. Rendering uses CPU SwiftShader rather than the training GPU; its HTTP server exists only while the render script runs and binds to loopback.

Validation performed: original-geometry GLB vertices match the frozen source meshes; all exported centers match the accepted map; all GLBs are self-contained glTF 2.0; the offline Chromium viewer loads and its opacity, visibility, orbit rotation, and reset controls work. The transparent PNG has a true alpha channel.
